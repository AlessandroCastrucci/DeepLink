app-banner demo

The banner is injected above this page. This demo uses data-show-android-only="false" so you can preview it on desktop; in production you usually omit that so only Android users see it.

How to use the banner

Host dist/app-banner.umd.cjs on your site or CDN, then add a single script tag on any page that should offer “open in app.” The tag must include data-app-banner (marker) and data-package (your Google Play application id). Other options are optional data-* attributes. 

<script
  src="/path/to/app-banner.umd.cjs"
  data-app-banner
  data-package="com.example.app"
  data-title="Example"
  data-description="Get the app for the best experience."
  async
></script>

Run this project locally: from the repo root run npm run demo and open http://localhost:4173/demo/. On a phone on the same Wi‑Fi, use your machine’s LAN IP instead of localhost to test real Android intent behavior.

Configuration (data-*)

Attribute Required Notes
data-app-banner yes Identifies the loader script (value may be empty). Required so async scripts can be found.
data-package yes Play Store package name (applicationId). Used in the intent and default store URL.
data-title no Banner title. Default App.
data-description no Subtitle under the title.
data-deep-link no Full URL passed into the Android intent. Defaults to the current page URL when the script initializes (same origin/path/query/hash as this page unless you override).
data-icon no Square image URL for the icon.
data-play-store-url no Overrides the fallback store URL entirely. If set, data-play-referrer is not merged in; put any query string you need in this URL.
data-play-referrer no Install attribution string appended as &referrer= on the default Play URL (not used when data-play-store-url is set). Example: utm_source=webapp or key=value pairs.
data-open-fallback-enabled no true / false (default true). After Open, if the page never becomes hidden (user did not switch to another app), redirect to the Play URL after the timeout—covers cases where the intent path does not leave the browser.
data-open-fallback-timeout-ms no Milliseconds to wait before that redirect (default 3000). Use 0 to disable the timer.
data-dismiss-days no After the user dismisses the banner, hide it for this many days (default 7).
data-show-android-only no true / false. Default true (only show when UA looks like Android).
data-open-button-text no Label on the primary button (default Open).
data-theme no light, dark, or auto (follows system).
data-storage-key no Suffix for localStorage dismiss state; default is the package name.

Deep links and what happens when the user taps Open

On Android Chrome (and other browsers that support Android intent URLs), tapping Open navigates to a single Chrome intent URL. That intent tells the system to open your app for a given deep link, using your data-package, and if the app is not installed, to open the Play Store instead.

The banner builds this shape (see Chrome’s Android intents documentation):

intent://<host path query hash>#Intent;
  scheme=<deep link scheme>;
  package=<data-package>;
  S.browser_fallback_url=<encoded Play Store URL>;
end
  • Deep link input comes from data-deep-link, or defaults to the current page URL. It must be a valid absolute URL with a scheme (e.g. https://, http://, or a custom scheme like myapp://…).
  • The SDK parses that URL and sets scheme= to its protocol (without the colon), so HTTPS App Links use scheme=https; a custom scheme uses your app’s scheme name.
  • The intent://… host/path segment mirrors the deep link’s host, path, query string, and hash so the same resource path can open in the native app when links are verified (Digital Asset Links / intent filters).
  • Intent fallback URL: S.browser_fallback_url is the resolved Play Store URL (default details?id=<package> plus optional data-play-referrer as &referrer=, or a full data-play-store-url override).
  • Visibility + timeout fallback: after Open, the SDK listens for visibilitychange. If the document stays visible for data-open-fallback-timeout-ms (default 3s), it navigates to the same Play URL—useful when the intent does not hand off to the app. Set data-open-fallback-enabled="false" or timeout 0 to turn this off.

Not guaranteed on every environment: in-app browsers, desktop Safari/Chrome, or OS versions may ignore intents or open the store in a tab instead of the Play app. Test on real Android devices with your real package id and verified deep links.
